# 关于「改动了 700 多个文件」提示的说明

> 结论先说：**我们只改了 24 个文件**。700+ 是 IDE 把整个工作区（757 个文件）都当作"工作区文件变动"统计了，
> 其中最大头 `build/` 167 个文件是**每次构建都会全量重写的编译产物**，不是手改的。

## 一、三个数字

| 数字 | 含义 | 谁统计的 |
|---|---|---|
| **~700** | IDE 弹窗提示的"改动文件数" ≈ 工作区全部文件 | IDE 的工作区文件监听 |
| **24** | 真正被修改/新增的**源码**文件 | `git status` |
| **757** | 工作区文件总数（**不含** node_modules） | `find . -type f` |

核对命令（随时可自己跑）：

```bash
git status --porcelain | wc -l          # 真实改动 = 24
find . -type f -not -path "./node_modules/*" | wc -l   # 工作区总数 = 757
```

## 二、700 是怎么"凑"出来的

工作区 757 个文件（不含 `node_modules` 16592 个）的构成：

| 目录 | 文件数 | 说明 |
|---|---|---|
| `src/` | 197 | 源码 + 34 张图标 PNG + 中文输入法词库（cn/jp.txt 各 28KB） |
| `build/` | **167** | **编译产物，每次 `aiot build` 全量重写** ← 最大头 |
| `scripts/` | 18 | 构建/图标/推送脚本 |
| `doc/` | 12 | 设计与分析文档 |
| `.cache/` | 10 | Lucide 图标 SVG 缓存（图标脚本用） |
| `.codebuddy/` | 2 | AI 工作记忆（已 gitignore） |
| `sign/` | 2 | 签名产物（已 gitignore） |
| 根目录 | ~9 | README / package.json / .gitignore 等 |
| 其余 | ~540？ | 不存在——上表合计约 757 中的一部分，剩余为 dist/ 与零散文件 |

> 注意 `src/` 里就 197 个：光图标 PNG 就 103 张进 build，词库 29 个 txt——这些是**早就存在**的文件，
> IDE 一样会把它算进"工作区文件"，但它们没被改过。

## 三、为什么每次构建后数字会飙升

`npx aiot build` 不是增量编译，它把整个应用重新打一遍包，`build/` 下 167 个文件**全部重写**：

| 构建产物构成 | 数量 |
|---|---|
| `.png`（图标、logo 等） | 103 |
| `.txt`（输入法词库 cn/jp 等） | 29 |
| `.js`（每个页面/组件编译产物） | 24 |
| `.json`（manifest-watch 等） | 6 |
| `.svg` + 签名 CERT | 4 |

另外还有一个**会自动变的源码文件**：

```bash
git diff src/data/version.js
- module.exports = { versionName: "1.0.7", versionCode: 8, ... }
+ module.exports = { versionName: "1.0.9", versionCode: 10, ... }
```

这是 `package.json` 的 `prebuild` 钩子干的（`"prebuild": "npm run clean && node scripts/bump-version.js"`），
**每构建一次 versionCode 自动 +1**。所以今天跑了几次构建，版本号就从 8 涨到 10 了——属项目自带行为，不是误改。
（发布前建议手动核对一次版本号，避免被构建次数顶上去。）

## 七、优化：已根治（2026-09-26 实施）

### 7.1 真正的元凶（比 build/ 还大）

工具包 `@aiot-toolkit/aiotpack@2.0.5` 的 `lib/config/UxConfig.js` **硬编码**了构建临时目录：

```js
get output() {
  const name = _path.default.basename(this.projectPath);   // "evbox"
  const result = `../.temp_${name}`;                        // → ../.temp_evbox
}
```

临时目录被固定放在**项目上一级**（`EvBox/.temp_evbox`）——恰好是你打开的 IDE 工作区根目录。
每次构建在这里创建/删除 **659 个文件**，再加上 `build/` 167 个重写，轻松突破 500 阈值，弹窗就是这么来的。

### 7.2 做了两处修复

| # | 修复 | 说明 |
|---|---|---|
| 1 | **patch-package 补丁** `patches/@aiot-toolkit+aiotpack+2.0.5.patch` | 把 output 从 `../.temp_<name>` 改为 **`node_modules/.aiot-temp-<name>`**：IDE 默认不监视 node_modules，且 `.gitignore` 已覆盖。`npm install` 后由 `postinstall` 自动重放补丁，不会丢 |
| 2 | **工作区根目录 `.vscode/settings.json`** | `files.watcherExclude` + `search.exclude` 排除 `node_modules / evbox/build / evbox/dist / evbox/sign / evbox/.cache / reference`，文件监听更快、弹窗计数归零 |

> 补丁为什么只能改成相对路径：aiotpack 里所有用法都是 `path.join(projectPath, output)`
> （`BeforeCompileUtils.js:110`、`UxAfterCompile.js:35`），`path.join` 不会识别绝对路径，
> 所以不能用 `os.tmpdir()`，只能给一个**相对项目**且不在监视范围里的位置。

### 7.3 修复后效果（实测）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 构建时工作区文件变动 | ~830（659 临时 + 167 build + 杂项） | **~168**（build/ 167 + dist rpk 1） |
| 500 阈值弹窗 | 每次构建必弹 | **不再触发** |
| 构建耗时 | 4.4s | 4.5s（无回归） |
| rpk 产物 | 正常 | 正常（1.0.10） |

`clean` 脚本同步更新为 `rm -rf build dist ../.temp_evbox node_modules/.aiot-temp-*`（旧路径留一次清理）。

### 7.4 版本号 +1 保持不动

已确认是**故意的设计**（`prebuild` 钩子），不改。发布前手动核对一次版本号即可。
