## 0. 一句话方案

> **计算器**：胶囊屏 4 列 × 5 行、按键 **40×52px**、数字 **30px**、结果 **36px**、按键即震动反馈；
> **农历**：胶囊屏「今日超大农历日（48px）」+「本月列表」+「查日（步进器，可一键存为倒数日）」，**胶囊屏不做 7×6 网格**（格子只有 22px，必然不可读）。

## 一、第一性要求：把"精美 / 大字号 / 好点按"量化

设计任何一屏之前，先满足下面这张表；**不满足就不算完成**。

| 维度 | 硬指标 | 为什么 |
|------|--------|--------|
| 中文最小字号 | **≥22px**（胶囊屏底线，见 `capsule-font-standard.md`） | 20px 以下汉字视角 <18 arcmin，不可读 |
| 数字/结果字号 | **≥28px**，核心数字 **36px**，农历日 **48px** | 数字笔画简单，可放大；这是"抬腕一眼"的关键 |
| 可点区域 | 主按钮 **≥52px 高**、**≥100px 宽**；网格键 **≥40×52px** | 手指 ≈8-10mm，宁大不小 |
| 键间距 | **≥4px**（网格键）、按钮间距 **≥12px** | 防误触 |
| 触控热区扩展 | 视觉高度不足 52px 时，外层 wrapper 上下各补 **8px** | 视觉不变、命中率提升 |
| 对齐 | 同一页所有左右边缘对齐到 **8px 栅格**；文字左对齐、数字右对齐 | 精美感 90% 来自对齐与留白 |
| 留白 | 内容区四周 **≥30px**（顶部/底部避让半圆），左右 **16px**（键盘区可放宽到 8px） | 胶囊两端半圆遮挡 |
| 字号档位 | 只用 6 个档：**48 / 36 / 30 / 28 / 24 / 22**（+ 20 仅脚注） | 禁止 25px、27px 这类"随手值" |
| 颜色 | 全部取自 `store.getTheme`（`bg/card/cardLight/accent/text/textSecondary/textMuted/border`） | 一次改主题全站跟随 |
| 圆角 | 按键 **12px**、卡片 **12-16px**、主按钮 **26px 全圆角** | 胶囊屏用大圆角呼应屏幕 |
| 动效 | 只做"按下即震动（`vibrator short`）+ 按压态色变"，**不做缩放/位移动画** | 手环上动画=掉帧；且规范禁止 `transform: scale` |
| 禁用 | **禁止 emoji**（项目实测手环渲染成方框）、禁止 `transform: scale` 缩放字号 | 已在项目里踩过 |
| 首屏性能 | 单帧渲染节点 **<200**（超过会触发看门狗复位）；月历等重复节点 **分帧挂载** | 参考工程实测红线 |

## 二、胶囊屏几何（先算再画）

```
胶囊屏 192 × 490，两端半圆 R=96，圆心 (96,96) 与 (96,394)
┌──────────┐  y=0    ← 0~30px：不可用（半圆顶）
│          │  y=30   ← 从这里开始放内容；30~96 只放"图标类"控件，禁止放文字
├──────────┤  y=96   ← 安全矩形区开始（全宽 192）
│  192×298 │  y=96~394  完全可用
├──────────┤  y=394  ← 安全矩形区结束
│          │  y=460  ← 内容应在此结束
└──────────┘  y=490
```

| 值 | 胶囊屏 | 圆屏（≈480 宽） | 方屏（336 宽） |
|----|--------|----------------|----------------|
| 内容区宽 | **160px**（两侧各 16px）；键盘区可放宽到 **176px**（两侧 8px） | ≈408px | ≈304px |
| 内容区高 | **430px**（上下各 30px） | ≈392px | ≈448px |
| 顶部只放图标 | ✅ 返回按钮 40×40 放在 y=30~70 | — | — |

> **键盘区为什么要放宽左右 padding**：按键本身就是最大的热区，额外留白只会让按键变小。这是对 16px 规则的**有意偏离**，仅限键盘/网格区域，文字区域仍用 16px。

## 三、工具一：计算器 `pages/calculator`

### 3.1 功能范围

| 优先级 | 能力 |
|--------|------|
| P0 | 四则运算、小数、正负号、百分号、退格、清除（C / AC 两级）、连续运算（`2+3+4`）、除零提示 |
| P1 | 历史记录（最近 20 条，`storage: calc_history`）、点击历史回填、结果长按复制到剪贴板 |
| P2 | 单位换算入口（不做成第二个工具，作为计算器的"模式"存在） |

### 3.2 键位与尺寸（三种屏型）

**胶囊屏（首选形态）** —— 内容区 176px，4 列 × 5 行：

```
   内容区 176px = 4 × 40 + 3 × 5(间距)
┌──────┬──────┬──────┬──────┐
│  C   │  ⌫   │  %   │  ÷   │   ← 功能行（22px 字号，textSecondary 底）
├──────┼──────┼──────┼──────┤
│  7   │  8   │  9   │  ×   │   ← 数字 30px 白字 / 运算符 30px accent 字
├──────┼──────┼──────┼──────┤
│  4   │  5   │  6   │  −   │
├──────┼──────┼──────┼──────┤
│  1   │  2   │  3   │  +   │
├──────┼──────┼──────┼──────┤
│  ±   │  0   │  .   │  =   │   ← = 用 accent 实底 + bg 色字（视觉焦点）
└──────┴──────┴──────┴──────┘
按键 40 × 52px，间距 5px；键盘总高 5×52 + 4×5 = 280px
```

| 屏型 | 列 × 行 | 键尺寸 | 间距 | 键盘总高 | 键盘总宽 |
|------|---------|--------|------|----------|----------|
| 胶囊 | 4 × 5 | **40 × 52** | 5 | 280 | 175（≤176 ✅） |
| 圆屏 | 5 × 4 | **68 × 62** | 8 | 272 | 372（≤408 ✅） |
| 方屏 | 4 × 5 | **70 × 56** | 8 | 312 | 304（≤304 ✅，正好占满） |

垂直预算校核（胶囊）：`30(顶) + 44(返回行) + 6 + 76(显示区) + 10 + 280(键盘) + 30(底) = 476 ≤ 490` ✅ 余 14px。

### 3.3 字号与配色

| 元素 | 胶囊 | 圆/方屏 | 颜色 |
|------|------|---------|------|
| 表达式（上一行小字） | **22px** | 26px | `textMuted` |
| 结果（主数字） | **36px**（3 位数以上降到 30px） | 44px | `text`，出错时 `deleteText` |
| 数字键 | **30px** | 34px | `text` |
| 运算符键 | **30px** | 34px | `accent` |
| 功能键（C/⌫/%） | **22px** | 26px | `textSecondary` |
| `=` 键 | **32px** 加粗 | 36px | 字 `bg`／底 `accent` |
| 键底色 | `card`；运算符/功能键底色 `cardLight`/`border` | 同 | — |

### 3.4 显示区规则

- 两行结构：上行表达式（超 12 字符右对齐截断为 `…`），下行结果（**右对齐**）。
- 结果长度自适应：≤5 字符 36px；6-8 字符 30px；>8 字符 24px 并允许横向滚动查看，**不允许省略号**（数字被截断是致命的）。
- 除以零 → 显示「不能除以 0」，2 秒后自动恢复上一个结果。
- 最多 12 位有效数字；超出时用科学计数法 `1.2346e9`（不用"万亿"等中文单位，避免与金额语义混淆）。

### 3.5 交互与反馈

| 操作 | 反馈 |
|------|------|
| 任意按键 | `vibrator.vibrate('short')`（**这是手环相对手机的独占优势，必须做**） + 按压态色变（用 `:active` 或 `onTouchDown/Up` 切底色） |
| `C` | 第一次清空当前输入，已清空时点第二次 = AC（全清） |
| `⌫` | 长按 600ms 连续退格 |
| `=` | 结果区闪烁一次（换 `accent` 色 150ms） |
| 出错 | 结果区变 `deleteText` + 短震两次 |

### 3.6 计算内核（避免 `eval` 与浮点误差）

```
状态：{ cur: "12.5", prev: null, op: null, expr: "12.5 × 3" }
按键 →
  数字/小数点：cur 追加（小数点只允许一个；整数位最多 12）
  运算符：若 prev 为 null → prev = cur, op = 新运算符
          否则 → prev = calc(prev, cur, op), op = 新运算符, cur = "0"
  =     ：结果 = calc(prev, cur, op)，expr 变为完整表达式，cur = 结果
  ±     ：cur 取反；% ：cur / 100（若处于 a×b% 语义则按 a×b/100 处理）
```

- 浮点误差：计算结果统一 `Math.round(v * 1e10) / 1e10` 后 `String()`，去掉 `0.30000000000000004` 这类脏值。
- **不使用 `eval`/`Function`**（JSC 字节码环境与安全都不合适）。
- 除法前先判 `cur === 0` → 报错，不产生 `Infinity`。

## 四、工具二：农历 `pages/lunar-calendar`（胶囊屏优先）

### 4.1 视图一「今日」（默认视图，抬腕即读）

胶囊屏布局（内容区 160 × 430）：

```
┌────────────────────────┐  y=30
│ ◀                      │  返回按钮 40×40（图标，允许放在半圆区）
│                        │
│  腊 月                  │  36px accent 加粗         ← 农历月
│  廿 五                  │  48px accent 加粗         ← 农历日（本页视觉核心）
│  2027-01-22 星期五       │  24px textSecondary
│  ┌──────────┐          │
│  │ 春节 · 还有 7 天 │    │  24px，chip 底 cardLight、字 accent
│  └──────────┘          │
│                        │
│  丙午 · 马年            │  22px textMuted（干支 + 生肖）
├────────────────────────┤
│  接下来                  │  24px textSecondary   ← 未来节日（3 条）
│  春节 · 02-17 · 7天      │  28px text / 24px accent
│  元宵 · 03-05 · 23天     │
│  情人节 · 02-14 · 4天    │
└────────────────────────┘  y=460
```

- 「农历日」与「农历月」拆成两行、日更大：`廿五` 两字 @48px 在 160px 宽内绰绰有余，且**字形复杂也能一眼辨认**（这是农历页最重要的信息）。
- 视图切换：底部三个 **28px 文字 tab**（今日 / 本月 / 查日），tab 高 52px，等分 160px（每条 ≈53×52，满足热区）——**不用图标**（图标在 20px 下不可辨，文字更稳）。
- 若当天是节日（春节/中秋/除夕…），在月/日之间插入一个 chip（见上图），并**同时显示还剩几天**（节日倒计时）。
- 干支/生肖是"加分项"：`丙午 · 马年` 22px，不能抢主信息。

### 4.2 视图二「本月」

**关键设计决策：胶囊屏不做 7×6 网格。**

计算依据：内容区 160px ÷ 7 列 = **22px/格**，扣掉间距后每格 ≤18px —— 低于项目规定的 18px 绝对底线，且农历小字（初二、十五）根本放不下。**画出来就是不可用**。

| 屏型 | 本月视图形态 | 说明 |
|------|--------------|------|
| 胶囊屏 | **列表**：本月每一天一行（`农历廿五  ·  01-22 周五`），节日行用 accent 高亮并用 chip 标注 | 每行 52px 高，正好 8 行可见，可滚动；行本身就是热区 → 点击进「查日」 |
| 圆屏 / 方屏 | **7 × 6 网格**（格子 48×48 / 40×40，公历数字 24px + 农历小字 18px，节日格 accent 底） | 大屏放得下，且格子可点 |

- 网格渲染注意：42 格 × 3 个 text = 126 节点，接近 200 红线 → **按行分帧挂载**（每次 2 行，`setTimeout` 16ms），与 `index.ux` 的做法一致。
- 本月视图顶部固定一行「本月节日」摘要（24px），让用户不滚动也能看到重点。

### 4.3 视图三「查日」（把农历变成可用的工具，而不只是展示）

- 复用倒数日编辑器里的**年/月/日步进器**（56×40 的 −/＋ 按钮 → 胶囊屏 48×40，已是项目既有形态），切换 公历/农历。
- 输出：双历对照（`公历 2027-06-07` / `农历五月初三`）+ 节日 + **距今天数**（复用 `countdown.diffDays`）。
- 一行主按钮「**存为倒数日**」（全宽 160×52，accent 实底）：调用 `countdown.createItem` 写入 `countdownDays`，跳转倒数日页并 toast「已添加」。
  → 这就是两个工具之间的**闭环**：看到某个农历日期 → 一键变成倒数日 → 钉到首页大数字。

### 4.4 数据来源（禁止重复实现）

| 需求 | 用哪个已有能力 |
|------|----------------|
| 公历↔农历换算、闰月、月/日中文 | `src/lib/lunar.js`（`solarToLunar` / `lunarToSolar` / `formatLunar` / `monthText` / `dayText`） |
| 节日（含除夕判定） | `lunar.lunarFestival` / `lunar.solarFestival` |
| 距今天数、下一次发生 | `src/data/countdown.js` 的 `diffDays` / `nextOccurrence` / `toKey` / `parseKey` |
| 主题色 | `store.getTheme` |
| 中文输入（如需） | `pages/chinese-input`（本工具无输入需求） |

> 新增需求只有一项：**干支（天干地支）与生肖**。算法 10 行，直接放进 `lunar.js`：
> `tiangan = "甲乙丙丁戊己庚辛壬癸"[(lYear - 4) % 10]`、`dizhi = "子丑寅卯辰巳午未申酉戌亥"[(lYear - 4) % 12]`、`shengxiao = "鼠牛虎兔龙蛇马羊猴鸡狗猪"[(lYear - 4) % 12]`。

### 4.5 未做（明确排除，避免变成"万年历大杂烩"）

- ❌ 宜忌/黄历/冲煞（无可靠离线数据源，且与"抬腕一眼"的定位冲突）

## 五、通用实现约定

| 复用 | 农历页 **不新增数据文件**，直接 require `lib/lunar.js` + `data/countdown.js` |

### 5.2 页面骨架（两页共用同一套壳）

```html
<div class="page" style="background-color: {{ theme.bg }}">
  <!-- 胶囊屏半圆区：只放图标，不放文字 -->
  <div class="top-bar">
    <div class="back-btn" onclick="goBack">…icon_back…</div>
  </div>
  <div class="body">  <!-- flex: 1, 分帧挂载区 --> </div>
  <div class="tab-bar">…今日 / 本月 / 查日…</div>  <!-- 仅农历页 -->
</div>
```

样式必须写**三套 media query**（沿用项目既有约定）：

```css
/* 默认（方屏） */ .key { width: 70px; height: 56px; font-size: 34px; }
@media (shape: circle) { .key { width: 68px; height: 62px; } }
@media (shape: capsule), (shape: pill-shaped) {
  .page { padding: 30px 8px 30px 8px; }   /* 键盘页左右 8px */
  .key { width: 40px; height: 52px; font-size: 30px; border-radius: 12px; }
  .key-gap { margin: 0 2.5px; }            /* 间距 5px 的一半，避免 flex gap 兼容问题 */
}
@media (shape: rect), (shape: rectangle) { … }
```

> 项目既有页面普遍用 `margin` 而不是 `gap` 控制间距，保持同一风格（`gap` 在部分运行时表现不稳）。

### 5.3 性能

- 键盘 20 键 + 显示区 ≈ 30 节点 → 安全。
- 农历「本月」列表 30 行 × 2 text = 60 节点 → 安全；圆/方屏网格按行分帧。
- 所有页面在 `onInit` 只做主题读取（`store.getTheme`），重活在 `onReady/onShow`，避免首屏卡顿。

### 5.4 包体积

| 项 | 预估 |
|----|------|
| 计算器页 | ≈12KB 源码（无资源） |
| 农历页 | ≈16KB 源码（无资源，全复用） |
| `lunar.js` | 已在包内（≈6KB） |
| 合计增量 | **< 30KB**（对比参考工程"中文输入法单页 233KB"，可忽略） |

## 六、实施步骤与验收

| 阶段 | 内容 | 验收 |
|------|------|------|

### 验收清单（逐条打勾，缺一不算完成）

- [ ] 胶囊屏**没有任何中文小于 22px**（农历小字若做，只能出现在圆屏/方屏网格）

- [ ] 所有颜色来自主题对象，切换主题后无"写死的蓝色"
- [ ] 无 emoji、无 `transform: scale`、无位移动画
- [ ] 首屏单帧节点 <200（网格页分帧）
- [ ] 农历换算与系统日历一致（至少对拍 2026-2027 的春节/中秋/闰月）
- [ ] 计算器不产生 `Infinity` / `NaN` / `0.30000000000000004`

## 七、风险与对策
