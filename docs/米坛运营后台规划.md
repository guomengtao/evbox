### 5.3 追踪方案：集成 go/ 系统 vs 独立新建

#### 现有 go/ 系统架构（已生产运行）

| 层 | 实现 |
|---|---|
| 存储 | Redis Hash `go:mapping`，key = slug，value = JSON `{ target_url, enabled, name_zh, name_en }` |
| 跳转 | `/go/<slug>` → 302 到目标 URL |
| 追踪 | 每次点击记录 IP/UA/Referer/Geo/deviceId → `tracking_events` + `visitor stats` |
| 管理 | 后台「购买点击日志」面板支持完整 CRUD + 最近 100 条点击明细 |
| API | `GET/POST/PUT/DELETE /api/admin/go-links` |

#### 对比分析

| | 集成 go/ 系统 ✅ | 独立新建 |
|---|---|---|
| 改动量 | 极小：批量 `redis.hset` 写入 slug 即可 | 大：需新建存储、追踪收集、管理界面 |
| 向下兼容 | **完全兼容** — Hash 新增 key 不影响已有 slug（如 `ev-timetable`） | 无影响 |
| 点击追踪 | **免费获得**：IP/UA/Geo/时间 全部自动记录 | 需从头实现 |
| 管理界面 | 复用「购买点击日志」面板，直接查看每个奖励链接的点击 | 需新建面板 |
| 对外 URL | `https://evbox.cc/go/evpro-c6f06ac8` 统一风格 | 需新建路由 |
| 风险 | **零风险** — 系统已在生产运行，逻辑成熟 | 新代码有 bug 风险 |

#### 结论：集成 go/ 系统

**Slug 命名规则：** `evpro-` + 兑换码前 8 位
```
原始链接: https://afdian.com/redeem/c6f06ac8a8e711f191c420
go/slug:  evpro-c6f06ac8
对外 URL: https://evbox.cc/go/evpro-c6f06ac8
```

**批量导入时自动创建 go/ 短链：**

```javascript
// 批量导入处理（在 catalog.js 或独立脚本中）
async function importRewardLinks(links) {
  for (var i = 0; i < links.length; i++) {
    var url = links[i].trim();
    // 从 URL 中提取兑换码
    // https://afdian.com/redeem/c6f06ac8a8e711f191c420 → c6f06ac8
    var m = url.match(/\/redeem\/([a-f0-9]+)/i);
    if (!m) continue;
    var code = m[1].substring(0, 8);
    var slug = 'evpro-' + code;
    
    // 写入 go/ 短链映射
    await redis.hset('go:mapping', slug, JSON.stringify({
      target_url: url,
      enabled: true,
      name_zh: 'EV课程表奖励 - ' + code,
      name_en: 'EV Timetable Reward - ' + code,
      note: 'BandBBS 五星评价奖励链接',
      created_at: Date.now(),
      updated_at: Date.now()
    }));
    
    // 写入奖励池
    await redis.hset('bandbbs:reward:pool', code, JSON.stringify({
      couponCode: code,
      redeemUrl: url,
      goSlug: slug,
      goUrl: 'https://evbox.cc/go/' + slug,
      assigned: false,
      claimed: false
    }));
  }
}
```

**关键优势：**
- 私信中发送 `go/` 链接，用户在 BandBBS 点击后 → 302 跳转到爱发电兑换页
- 点击事件自动进入 `tracking_events`（kind=`purchase_click`），可在「购买点击日志」面板按 slug 筛选查看谁已领取
- 已有 `ev-timetable` 等 slug 完全不受影响，各自独立

## 八、API 接口规划

| 操作 | 端点 | 说明 |
|---|---|---|
| 导入奖励池 | `POST /api/admin/catalog?kind=bandbbs&op=pool-import` | `{ links: [...] }`，自动创建 go/ slug + 写入奖励池 |
| 查询奖励池 | `GET /api/admin/catalog?kind=bandbbs&op=pool-list` | 返回库存统计 + 列表（含 goUrl） |
| 发送资源奖励 | `POST /api/admin/catalog?kind=bandbbs&op=send-rewards` | `{ resourceId }`，自动从池中取链接 + 发私信 |
| 重发单条奖励 | `POST /api/admin/catalog?kind=bandbbs&op=resend-reward` | `{ rewardId }` |
| 获取/保存话术 | `GET/POST /api/admin/catalog?kind=bandbbs&op=template` | 奖励话术模板 CRUD |
| 评论筛选查询 | `GET /api/admin/catalog?kind=bandbbs&op=reviews` | `?resourceId=&status=&page=` |

> **注意**：go/ 短链的 CRUD 复用已有 `/api/admin/go-links` 接口，不在 bandbbs 中重复实现。奖励池导入时直接写 Redis `go:mapping` hash。

## 十、注意事项

1. **go/ 短链向下兼容**：`redis.hset('go:mapping', slug, ...)` 新增 key 不影响已有 `ev-timetable` 等 slug。`go.js` 逻辑完全不变。
2. **兑换码提取**：正则 `/\/redeem\/([a-f0-9]+)/i` 从 URL 提取完整兑换码，取前 8 位（如 `c6f06ac8`）作为 slug 后缀和 pool key，兼顾唯一性和可读性。
3. **奖励池容量**：前端显示库存/已用/剩余，低于 5 个时红色预警。
4. **去重**：同一兑换码（前8位）不应重复导入。
5. **并发安全**：发送奖励时从池中取链接需标记为 `assigned=true`，防止同一链接发给两个用户。建议使用 Redis `HSETNX` 或 Lua 脚本。
6. **私信频率限制**：BandBBS API 可能有发送频率限制，批量发送时加入延时（如每条间隔 500ms）。
7. **回滚机制**：如私信发送失败，奖励池链接应保持未分配状态，不标记评论为已奖励。
8. **领取判定**：通过 go/ 系统的 `tracking_events`（kind=`purchase_click`）查询该 slug 是否有点击记录来判定用户是否已领取。
