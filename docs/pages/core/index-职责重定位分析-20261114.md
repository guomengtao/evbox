## 0. 结论先行

1. **v2 的定位错了，不是视觉没调好**。它把首页做成了「导航路由页」——只回答「去哪」；工具箱的首页应该回答「现在能用什么、有什么值得看」。这是**页面类型选错**：把首页按「内页／设置页／列表页」的做法处理了。那种场景简洁是对的，首页不成立。
2. **错得可量化**。ev-six §7 规定每屏文字预算 **48~60 字（8~10 行 × 6P）**；v2 只有 **5 行、约 20 字**，不到下限一半。**不是极简，是空。**
3. **ev-six 六位准则保留，且必须保留**（Tom 明确认可这条）。问题不在准则，而在「用正确的准则去承载了错误的内容」——准则管的是怎么排得下、看得清，不管该放什么。
4. **改法**：首页 = **默认推荐 2~4 款工具（每款带实时内容）＋ 用户钉选覆盖 ＋ 状态／焦点层 ＋ 一个全集入口**。首启有东西看，长期「用户喜欢什么就看什么」。
5. **仓里已有约 80% 的基础设施**：`tool-summaries.js`（7 类实时摘要）、`pin-helper.js`（任意页钉首页）、`TOOLS` 8 项、`homepage_settings`。v2 把它们全部压成了一个「已钉页面」链接 —— **等于把内容降级成目录**。

## 1. 首页到底要承载什么

### 1.1 场景：抬腕 2 秒

手环首页的使用场景是「抬腕 → 看一眼 → 放下」，不是「打开 App → 找功能」。首页的价值 = **不用点就能获得的信息量**。v2 要求用户先点 1~2 次才能看到任何内容，实际把首页做成了启动器。

| 页面类型 | 职责 | 合格标准 | v2 落在哪 |
|---|---|---|---|
| 欢迎页 | 品牌 + 进入 | 居中构图、有仪式感、一次即走 | — |
| **首页** | **抬腕即得的信息面 + 高频入口** | **不点也有内容** | ❌ 没做到 |
| 内页 / 设置页 / 列表页 | 单一任务的导航或配置 | 简洁、层级清楚 | ✅ v2 实际像这个 |

Tom 说「欢迎页还是居中的」——正因为欢迎页清楚自己是「一次即走」的门面，有构图、有重心；v2 两头不靠：既没有门面的仪式感，又没有首页的信息量。

### 1.2 产品趋势决定了「首页必须做选择」

`src/manifest.json` 注册 26 个页面，`tools.ux` 的 `TOOLS` 已有 8 项参与三视图，README 明确写「新增工具只需追加一条」——**工具只增不减**。8 项 × 58px = 464px 已超一屏，未来更多，首页不可能全列。于是选择权给谁：

| 方案 | 首启 | 长期 | 判定 |
|---|---|---|---|
| 全给产品（硬编码固定几个） | 有内容 | 用不上的永远占着首页 | 不灵活 |
| 全给用户（空白 + 自己钉） | **空的** | 完全贴合 | 「什么都没有」的另一个版本 |
| **产品给默认 + 用户可覆盖** | **有内容** | **可替换成自己喜欢的** | ✅ Tom 提的模式 |

### 1.3 承载清单（分层）

| 层 | 承载内容 | 可点 | 信息类型 | v2 |
|---|---|---|---|---|
| ① 状态层 | 时刻 / 日期（钟关时品牌 + 日期） | 否 | 抬腕即得 | ⚠️ 退化成一行品牌字 |
| ② 焦点层 | 倒数日大数字（开关与数据都已存在） | 是 | 抬腕即得 + 用户数据 | ⚠️ 有代码、本机无数据未出图 |
| ③ **推荐层** | **2~4 款工具卡，每款带实时摘要** | 是 | 抬腕即得 + 工具实时数据 | ❌ **完全没有** |
| ④ 入口层 | 全部工具（唯一一个导航行） | 是 | 去哪 | ⚠️ 被做成 4 个等权行之一 |
| ⑤ 系统层 | 设置 / 退出 / 钉页管理 | 是 | 低频 | ⚠️ 占了 2 行，与内容同权 |

**v2 缺的正好是 ②③ —— 缺的就是「内容」。** 补上这两层，首页才成立。

## 2. 核心机制：默认推荐 + 用户钉选覆盖

### 2.1 数据模型：统一成「首页槽位」

不要新造一套推荐系统，把它收敛成一份槽位列表：

```
homepage_slots = [
  { id, name, uri, summaryKey, source: "default" | "pinned", order }
]
```

- **首启（无配置）**：`default` 槽位 = 产品推荐的 2~4 款。建议默认 **3 款：倒数日 / 农历 / 一言** —— 这三类都有「每天不一样」的实时内容，最能撑起抬腕价值；计算器、二维码等是「用时才打开」，不适合占首页。
- **用户钉任意页**：追加 `pinned` 槽位；`pages/pinned-pages` 现有「取消」能力直接复用。
- **用户可移除默认项**（Tom 说「把这两款去掉，再选自己喜欢的」）：移除后不再自动回填；设置里保留「恢复默认推荐」。
- **不迁移、不破坏**：继续用 `pinned_pages` 这个 storage key，新增的只是「默认槽位」的读取与合并逻辑；`homepage_settings` 增 `homepageSlots` / `slotLimit` / `hideDefaults` 三个字段。

### 2.2 推荐卡必须带实时内容，否则又是一个列表

只放工具名 = 换皮的列表。推荐层要「承载东西」，就得让每款工具在首页直接给出一句当前的值：

| 工具 | 首页摘要（示意） | 数据源 | 现状 |
|---|---|---|---|
| 倒数日 | `项目截止 还有7天` | `tool-summaries.js` countdown | ✅ 已有 |
| 农历 | `冬月十四` | lunar | ✅ 已有 |
| 计算器 | `上次 42` | `calc_history` | ✅ 已有 |
| 二维码 | `3 个` | `qrcode_items_list` | ✅ 已有 |
| 震动 | `2 个方案` | `vibration_presets` | ✅ 已有 |
| 一言 / 抉择 / 答案 | 当日一句 / 88 组预设 / 今日一答 | `daily-quote` / `decide` / `answer-book` | ⚠️ 需补 TASKS 条目 |

`tool-summaries.js` 已有 7 类取数，且注释明确「任一来源取不到 → 摘要为空，UI 不渲染那行，绝不显示未知／加载中」——正好符合 ev-six 的故障可见性要求，可直接接。

> ⚠️ **待处理**：现有摘要文案带 `·`（如 `项目截止 · 7天`），违反 ev-six §5 禁分隔符。首页消费时必须改成「换行」或纯排版分隔，不能原样搬。

### 2.3 数量与高度预算（ev-six 硬约束）

单屏可用 **434px**（490 − 40 顶 − 16 底），1.5 屏上限 **735px**。沿用 v2 已落地的组件高度：

| 组件 | 高 |
|---|---|
| 页 padding | 56 |
| 状态层 | 106（钟开）/ 50（钟关） |
| 焦点卡 | 128 |
| 一张推荐卡（28px 名称行 38 + 24px 摘要行 34 + 上下 10×2） | 92，卡间距 10 → 每增一款约 102 |
| 一个入口行 | 58 |
| 系统行（可选） | 2×58 + 10 = 126 |

| 配置 | 合计 | 判定 |
|---|---|---|
| 钟开 + 焦点 + **3 推荐** + 1 入口 | 56+106+128+306+58 = **654** | ✅ ≤735（1.5 屏，需滚动提示） |
| 钟关 + 无焦点 + **2 推荐** + 1 入口 + 系统行 | 56+50+204+58+126 = **494** | ✅ 约 1.1 屏 |
| 钟开 + 焦点 + **4 推荐** + 1 入口 | 56+106+128+408+58 = **756** | ❌ 超 735 |

**结论：默认 3 款是上限内的最优解**；4 款必须关掉焦点卡或状态层才成立；2 款偏空。建议默认 3 款、允许用户在 2~4 间调；超一屏用滚动提示，**绝不压字号** —— 完全沿用 ev-six §7。

### 2.4 「推荐」二字不能出现（与 ev-six 不冲突）

ev-six §5 与栏目方案 §4.3 禁的是**「推荐 / 备用」这类文字标签与徽标**，不是禁「默认给几款内容」这个产品机制。表达「这几款是产品给的」只能靠：

- **位置**：排在状态层／焦点层之下、全集入口之上；
- **内容**：有实时摘要，一看就知道有用；
- **底色**：用 `card` 层，不额外加标签。

即 **不写「推荐」，但用户一眼知道这几款是首页给的**。默认项与用户钉的项建议**混排、不做视觉区分**，避免把「产品选的」和「我选的」搞成主次。

## 4. 头部怎么处理

v2 头部只有一行 28px `Ev工具箱`，是「简陋」最刺眼处。三个方向：

| 方向 | 做法 | 评价 |
|---|---|---|
| **A 信息型**（建议） | 44px 时刻 + 24px 短日期；钟关时改为「品牌 + 日期」两行 | 信息量够，符合抬腕场景 |
| B 品牌型 | 欢迎页式居中构图（品牌 + 副标 + 一句） | 仪式感够、信息量低，更适合 `pages/welcome` |
| C 焦点型 | 倒数日大数字提到最顶，头部即内容 | 与焦点层合并，省 128px，可多放一款推荐 |

建议 **A + C 组合**：钟开时顶时刻，紧接倒数日焦点，推荐层在下；钟关时头部给「品牌 + 日期」两行，保证至少两行有信息。
另：`store.getHomepageSettings` 默认 `showTime: false`，导致首启头部空 —— 建议把默认值改 `true`（或首启引导开一次），否则新用户第一眼仍是空的。

## 5. 保留 / 推翻清单

**保留（ev-six，Tom 已认可）**
六位置 ≤6P、字号四档 44/30/28/24、页面 padding 12px / 卡片 8px、留白只从高度买、禁箭头 / 分隔符 / 徽标 / `text-overflow` / `showToast`、`display` 绑定、三级底色表达可点性、`subColor` WCAG AA 派生、1.5 屏 735px + 滚动提示、`onInit` try-catch 防黑屏、固定 40px 胶囊安全区。

**推翻（v2 的五项错误决策）**

1. 「首页只做去哪，工具全集交给 tools 页」→ 首页**必须承载内容**；
2. 「三视图全删、10 个工具全删」→ 该删的是**平铺全量**，不是内容；应改为 3 张带摘要的卡；
3. 「钉页压成 1 个入口行」→ 钉页是首页内容的主要来源，应**直接上首页**；
4. 「每屏 32~40 字预算」→ **取错口径**：总纲 §3.21 是 48~60 字，手册 §八 的 32~40 是课程表场景下限，不适用于工具箱首页；
5. 「4 个等权操作行」→ 把导航和系统操作抬到与内容同权；应只留 1 个导航行，设置 / 退出收进 `pages/settings`。

### 8.4 排障真因（避免下一轮重复踩）

1. **按字符硬裁出残句**：`示例：距离期末还有 30 天` 被 6P 裁成「示例：距离期」，
   `摸鱼是为了更好地工作` 被裁成「摸鱼是为了更」。改为 `clauseFit` 只在标点边界截完整分句，
   示例标题剥前缀后超预算就整段不显示（hero 卡靠卡名 + 大数字自解释）。
2. **`lines: 2` 本身违规**：曾尝试两行自动折行消除残句，实测第二个文本行不渲染、
   首屏仍只剩半句；且总纲手册第 8 条明令「禁折行、禁省略号，一行一意，宁可删字」。
   最终回归 `lines: 1` + 6P 完整短句，长句由 `tool-summaries.js` 按日取池内短句兜底。
3. **倒数日 44px 大数字不出现**：`countdownHero` 原为 `defer: 50ms`，
   `onShow` 时 `loadCountdownHero` 尚未挂载。改为同步 init，并在摘要落定后二次取值。
4. **`vela push` 热更新后应用不自起**：刷包 rc=0、guest 字节码正确，但 vapp 全退、
   fb0 恒零；必须重新前台 `vapp app/<pkg>` 驻留并 `tap 96 485` 唤醒才出图。
   `vela up` 对已有活实例会拒绝双开（同 AVD userdata 写锁），运行中实例只能走 `vela push`。
5. **多会话共用 guest**（`pit-20261114-176`）：出图前实读 guest manifest 版本 / entry /
   `index.jsc` 字节数，串成单条命令不留抢占窗口。
