## 1. 页面职责

从一组选项里公平地抽一个，把「抽」做得有仪式感。纯本地、无外部服务。工具箱 `tools.ux` 已加入口「抉择」，图标 `tool_decide.png`（dark／light 两套）。

**结果形态**（`drawRule.resultMode`，见方案 §3.7 / §3.8）：

| 形态 | 输出 | 分期 | 当前状态 |
|---|---|---|---|
| `single` | 1 个元素（默认） | P0 | ✅ 已实现 |
| `multi` | 同集合挑 k 个，单次内不重复 | P1 | ✅ 基础版（k ≤ 3） |
| `partition` | 全覆盖分组 | P2 | 未实现 |
| `combo` | 跨集合各抽一个拼成元组（如蔬菜＋水果＋粥） | P1 尾–P2 | ✅ 基础版（三槽串行 + 汇总卡） |

首页开关 `homepage_settings.showDecide` 与 `pinned_pages` 钉首页入口属 P1，目前仅工具箱入口。

## 2. 界面结构（实际实现）

一屏只做「抽」这一件事，四个视图用 `display` 绑定切换，共用同一个页头（返回键 30 + 居中标题 28px ≤2 字 + 等宽占位 30）：

```
┌ 抉择                            28px 页头 ┐
│ 当前卡组名                      28px 可点  │
│ ── 抽取舞台 138px ─────────────────────  │
│   spinning: 3 行窗口 / flip 单行 28px     │
│   done:     结果大字 44px lines 2         │
│            或多人结果 24px 逐行            │
│ 抽一个 / 再抽一次               28px 主按钮│
│ 抽几个（可点步进）              24px 次行 │
│ 我的卡组                        24px 次行 │
│ 内联状态条                      24px 固定 │
└──────────────────────────────────────┘
```

**罗盘模式**是另一套布局：点盘面即抽，隐藏主按钮／两个次行／状态条，把纵向空间全让给盘面。盘面文字固定水平排布，只有一根指针在动；结果以 44px 大字显示在盘面下方，不与刻度抢位置。

- **卡组视图**：两级 —— 先选 12 个分类（短名），再选该类下的卡组。P1 后续才做分类折叠／最近使用／收藏／搜索。
- **自定义视图**：逐项添加 → 保存并抽。手环无软键盘，复用 `pages/chinese-input` 的 storage 回传协议（见 §7.2 坑 3）。
- **动画**：`flip`（2 项，单行快速切换）、`wheel`（≥3 项，3 行窗口程序驱动逐帧减速）、`compass`（≤8 项，指针逐帧转动）。统一状态机 `idle → spinning → done`，**结果在 `draw()` 里先定后演**；`onHide` 中断动画直接跳到结果，不改变结果。
- **罗盘自动回退**：`anim === "compass"` 且 `pickCount === 1` 且项数不超屏型上限（圆屏 8／胶囊屏 4）且每个标签 ≤2P 才进罗盘，否则一律回退 `wheel`。11 组 compass 预设中胶囊屏可用 7 组、圆屏 11 组全部可用；12 项组本来就没标 compass。
- **餐饮两个入口都在「餐饮」类的卡组列表末尾**，是视图入口不是新卡组：F01「今天吃什么」的 `items` 为空占位，运行时由 `preset-food.json` 接管，列表里跳过它不显示为死项。
  - 「随便吃一道」= **OR**：12 个 L1 大类选 1 类 → 该类 20–30 项走 wheel 抽 1 个。
  - 「搭配抽」= **AND**：三槽各抽 1 项 → 逐槽串行揭晓 → 汇总卡（`combo` 视图）。两者共用同一份 300 条数据，未新增任何条目。
- **组合结果卡**按 ev-six 用纵向排版代替分隔符：每槽一张底色卡片，字段标签 24px 一行、字段值 28px 一行；三槽 6 行加标题 1 行与操作行 1 行 = 8 行，正好贴一屏文字预算上限。组合视图隐藏次行，返回靠页头返回键。

## 3. 核心方法（实际实现）

| 方法 | 职责 |
|---|---|
| `setDeck(deck)` | 装载卡组，重置抽取状态，调用 `resolveAnim()` |
| `resolveAnim()` | auto 策略：抽取规则优先 → compass 语义 → 项数与屏型上限 → 回退 flip／wheel |
| `readShape()` | `@system.device.getInfo` 读 `screenShape`，回调里重算动画与盘面尺寸 |
| `buildDial()` / `updateNeedle(frame, hitIndex)` | 生成圆周刻度（角度量化到 15° 帧）、切换指针帧图与命中高亮 |
| `pickIndices()` | Fisher-Yates 洗牌取前 k 个，强制 `replace=false`（单次内不重复） |
| `changePick()` | 「抽几个」步进，上限 3；回到 1 时自动恢复 flip |
| `draw()` / `tick()` / `tickCompass()` / `finishDraw()` | 先定结果，再逐帧减速；到点强制对齐命中帧并落结果 |
| `buildWindow()` | 构造 3 行滚动窗口（中央高亮）或 flip 单行；罗盘模式直接跳过 |
| `buildCatList()` / `pickCat(idx)` / `selectDeck(idx)` | 两级卡组列表；分类用 `CAT_SHORT` 短名 |
| `addItem()` | 写 `chinese_input_*` 参数 → `router.push` 到中文输入页 |
| `checkInputResult()` / `parseText()` / `posOf()` | 回传解析：空格／逗号／顿号／分号拆分、去重、≤6P 过滤、上限 30 项 |
| `saveCustom()` / `clearCustom()` / `saveDraft()` / `loadDraft()` | 自定义卡组与草稿的 `@system.storage` 持久化 |
| `loadCustomDeck()` | 读回自定义卡组并追加「我的」分类 |
| `openFoodCats()` / `selectDeck(-10-i)` | 餐饮 OR 两级抽取：12 个 L1 大类 → 选定类目转为 wheel 卡组 |
| `resolveSlot(slot)` | 解析 `deck:food/<类名>` 与 `deck:preset/<id>`，按 `filter` 缩候选集，只读不新增条目 |
| `startCombo()` / `drawCombo()` / `runSlot()` | 组合 AND：一次性抽定三槽结果，再逐槽串行揭晓 |
| `buildSlotWindow()` / `tickSlot()` / `finishSlot()` / `finishComboNow()` | 槽级 3 行窗口动画、汇总卡累积、中断时直接落全套结果 |

> 骨架期写的 `loadDecks()` / `runAnimation()` / `deleteDeck()` 仍未实现；`drawRule` 目前只落地了 `pickCount` 与 `replace=false` 的语义（未做完整字段对象）；`src/lib/crypto.js` 随机源仍留待后续（当前用 `Math.random()`）。

## 4. 数据字段

P0 实际使用的子集：`id` / `title` / `cat` / `items` / `anim` / `hint`。P1 第一批新增运行时字段 `pickCount`（不落盘、不写进 JSON），语义对齐方案 `drawRule.pickCount`。P1 尾新增独立数据文件 `src/data/decks/preset-food.json`（12 类 / 300 条），与 88 组预设分离。

`preset-food.json` 每条含 `name` / `sub` 与四类筛选标签 `口味` / `荤素` / `冷热` / `场景`（中文键，与方案 §3.5.4 / §3.8.3 示例口径一致）。`sub` 是配额表里的收录维度（如「粥」「素」），让槽位能精确取子集 —— 否则「粥」槽只按「热食」筛会从粉汤粥类里抽出螺蛳粉。标签由确定性规则生成（荤素看食材词、辣看辣味词、冷热看冷食词、场景看速食外卖词），**只缩小候选集，不排序不打分**。

`combos[0]` 定义午饭三槽：`蔬菜` 取家常菜中 `荤素=素 且 sub=素`（7 项）、`水果` 取预设 `E02 当季水果`（8 项）、`粥` 取粉汤粥中 `sub=粥 且 冷热=热食`（5 项）。`ref` 格式 `deck:food/<类名>` / `deck:preset/<id>`；`filter` 支持 `口味` / `荤素` / `冷热` / `场景` / `sub` 五个键，均可选。

方案定义的完整卡组模型（`deckId` / `category` / `source` / `mode` / `groups` / `animation` / `visualHint` / `allowRepeat` / `filters` / `drawRule`）与 `drawRule`（`resultMode` / `replace` / `groupSize` / `groupMode` / `groupLabels` / `slots`，全部可选）属 P2+，字段命名保持方案原样，实现时不得与 `mode` 混淆。

预设数据 `src/data/decks/preset-decks.json`：12 类 / **88 组**，屏显 `title` 一律 ≤6P 且不含禁符号；`anim` 直接标记动画，`hint=compass` 作语义标记（当前两者一致）。餐饮 300 项独立 `preset-food.json`（P1 后续），不计入 88 组。

## 5. ev-six 坑位清单（仍然有效）

1. **ev-six 是硬铁律，不是建议**：字号只有 `44 / 30 / 28 / 24` 四档，**24px 绝对下限**，12–23px 一律禁用；一行 ≤6P（汉字 1.0 / 拉丁数字 0.55 / 空格 0.3 / 全角标点 0.5 / 徽标 1.0，无免费字符）。`src/common/ev-six-tokens.css` 是规范正本；**页面把四档 class 内联写在 `.ux` 的 `<style>` 里**（快应用 `.ux` 不支持跨文件 `@import`，工程既有页面全部内联），两处口径必须同步，改一处要改另一处。
2. **留白只从高度买**：页面左右 padding 12px（内容宽 168px），卡片／行 ≤8px；横向 padding 直接扣位置预算，实测曾把文案截成「购买兑换」且不报错。
3. **禁符号三件套**：禁箭头、禁分隔符（分隔点带空格 = 1.1P）、禁序号徽标与「推荐／备用」标签。可点性靠**底色三级层次**（裸文／卡片／亮底）。预设 JSON 的 `title` 已按此口径取名（如「要不要」而非「要/不要」）；JSON 里的 `desc` 只作数据说明、不上屏，不参与屏显扫描。
4. **放不下时**：删内容 → 换行／拆页 → 抬 `line-height`（44→60 / 30→40 / 28→38 / 24→34）→ 纵向 padding → 纵向 margin；**绝不压字号**。
5. **屏型**：pill 192×490（内容宽 168px）／rect 336×480／circle 466×466。大屏只调 padding 与舞台高度，不缩字号、不放大字号。compass 上限 v7 收紧为**圆屏 ≤8 项、胶囊屏 ≤4 项**，12 项组回退 wheel。
6. **验收**：提交前过 `ev/class-schedule/docs/手环页面开工手册-20261023.md` §六 14 条自检；按总纲 §3.24 **ev-shapes 三屏同包并排**（pill / rect / circle），逐屏标版本；交付写「ev-six 通过 / 违 N 项」。
7. **路由 WIP 已裁定**：`src/manifest.json` 与 `src/data/version.js` 的他人版本号 WIP（1.0.63 / 64）按提交纪律**拆两个提交**处置 —— 先原样入库他人 WIP，再提交本页改动，未代为发布半成品、也未把两者混进同一提交。

### 7.4 P1 第一批实测（2026-11-14）

**范围**：指针式罗盘 + 基础多人抽取。领单 `evtask-D-evevbox-261114-txts3r`，认领 `4c1f25fa-82d7-4224-a776-88610c8b535c`。

**关键工程判断：不用 `transform: rotate()`**。全库检索 `transform`／`rotate(` **零用例**，而 `position: absolute`（tools / settings / calculator 等多页）与 `device.getInfo().screenShape`（chinese-input / index / calculator 等）都是已验证能力。直接写旋转 CSS 属于未验证能力，真机可能静默不渲染且编译不报错 —— 这是「静态扫描全绿但用户看不见」的典型陷阱。改为 **PIL 预渲染 24 帧透明指针图 + `image src` 动态绑定逐帧切换**，编译后逐张核对 rpk 内确实存在 24 个 `needle_*.png`。

**刻度与指针对齐**：盘面角度量化到 15° 帧（`Math.round(i*360/N/15)*15`），标签位置与命中帧共用同一套角度，因此 N=7 这类除不尽的情况指针也必然精确指向某个标签中心；自测 N=2..8 全部无角度碰撞、帧号落在 0–23。

**布局预算的两处主动收缩**（都是 ev-six 位置预算逼出来的，不是功能取舍）：
1. 罗盘模式隐藏主按钮／两个次行／状态条，点盘面即抽；圆屏 `.page` 上 padding 40→24。这样圆屏盘面 240px（R=90，8 项相邻中心距约 69px，24px 两字标签留白约 21px），胶囊屏盘面 160px（R=50，4 项中心距约 71px）。结果大字放在盘面下方而非盘心，避免 88px 宽的结果卡遮住刻度。
2. 「抽几个」行出现时隐藏冗余的「换卡组」行（卡组名本身可点），净增高度 0；多人结果 k 上限收到 **3**（3 行 ×34px = 102px < 胶囊屏舞台 126px），k ≥ 4 需拆页，留 P2。

### 7.9 抽取过程动画 + 按钮锁与硬兜底 + 一体返回胶囊（2026-11-14 23:20 +0800）

**领单** `evtask-D-evevbox-261114-4rn2yh` / 认领 `20261114-230548-75687`。

**背景**：1.0.70 经 Tom 真机确认「抽可以用了」，但点完瞬间出结果、没有过程感；按钮点了无变化，容易让人以为没反应而重复点。需求三条：① 有动画过程，尤其「抽两个」要有合适的形式；② 抽取中按钮变「正在抽取」并禁点防误触，**2 秒后必须重新激活，绝不能永久不能点**；③ 顶部返回改成易微课程表设置页那种「箭头 + 标题合成一颗胶囊、整块可点」的形式。

#### 动画设计：双签错峰开奖

不用骰子／跑动／transform rotate（全库无该能力用例），也不新引图片资源。结果舞台里加一层**全常驻三行文本**，抽两个时上下两行各自滚候选（每 90ms 换一次），按 `(k+1)/(count+1) × 1600ms` 先后定格：第一行约 533ms 停住并切 `accent` 高亮，第二行约 1066ms 停住，1600ms 正式揭晓。抽一个用中行单签、抽三个铺满三行逐张落定，三行块重心恒在舞台中心。

行位分配 `1 → [中]`、`2 → [上, 下]`、`3 → [上, 中, 下]`；候选用确定性伪随机 `items[(step*7 + k*13 + 3) % n]`，同一帧多次心跳不会闪字。罗盘模式复用同一心跳，逐帧换 `needleSrc` 指针帧图。

#### 架构：不把「有没有过程」押在定时器上

真机 JSC 已知「触摸回调里安排的 `setTimeout` 可能不派发」（§7.6），而 §7.8 又确认「一次触摸回调内跨方法写 data 只提交最后一批」。因此：

| 约束 | 做法 |
|---|---|
| 跨方法批次丢失 | `startSpin()` / `renderSpinFrame()` / `reveal()` 各自是**单方法连续赋值块**，起帧帧、过程帧、揭晓帧都不调用任何会写 `this` 的方法；纯函数 `frameAt()` / `rowSlots()` / `needlePath()` 只算不写 |
| 隐藏子树懒渲染 | 结果层**全常驻**：不切 `display`、不用 `if` 建节点、不用 `for` 数组（真机 `for` 数组更新不重绘）。三个 `.line` text 从首屏活到揭晓，靠内容空/非空表达状态；单行结果走常驻 44px 大字 |
| 定时器不派发 | 主链在 **`onReady` 起常驻心跳**（生命周期回调里安排的链可派发），点击只改状态字段、不在触摸回调里起主链。心跳按 `Date.now() - spinStart` **绝对时间**推帧，丢帧自动追上，不靠帧计数累加到终点 |
| 功耗 | idle 心跳降频 250ms，`spinning` 才 70ms；`onDestroy` 置 `pageAlive=false` 让多条自愈链自行终止 |

**三层解锁保险**（`REVEAL_MS=1600` < `HARD_LOCK_MS=2000`）：

### 7.10 三连抽「卷轴接力」动画（2026-11-14 23:35 +0800）

**领单** `evtask-D-evevbox-261114-c8ypha` / 认领 `20261114-233428-34819`。

**背景**：§7.9 把「抽两个」做成了双签错峰开奖，Tom 接着要求做下一组——「抽三个」要有**另一种**合适的动画，不能照抄双签。

#### 与双签的区别：一处动 vs 两处同时动

| | 抽两个（§7.9 双签） | 抽三个（本节 卷轴接力） |
|---|---|---|
| 滚动行数 | 上下两行**同时**滚 | **一次只有一行**在滚 |
| 定格节奏 | 533 / 1066ms 错峰 | 420 / 860 / 1300ms 接力 |
| 视觉读法 | 两条签一起摇，先后落地 | 名单逐条揭晓，一条定住、下一条接棒 |
| 空白行 | 无 | 未轮到的行**留空**，是「接力」的可见证据 |

`frameAt(el, count, lines, items)` 在 `count >= 3` 时走独立分支：行 `k` 只在 `[LOCK3[k-1], LOCK3[k])` 区间内滚动，`el >= LOCK3[k]` 后钉住为结果并切 `accent`，尚未轮到的行保持空串。三条落定后到 1600ms 揭晓留 300ms 静止，让「三条都定了」被看清，不再干等 460ms。

#### 减速停

落定前 180ms（`ROLL_SLOW`）把候选索引推进改成 `floor(step/3)`：心跳帧率不变，但文字切换频率降到 1/3，读起来是「沉一下再停」而不是硬切。这是纯函数计算，不增加任何定时器，天然符合 §7.9 的架构约束（心跳按绝对时间推帧、揭晓幂等、三层解锁不变）。

#### 两个实现坑

1. **假滚**：原轮播下标用 `(step*7 + k*13 + 3) % n`，当卡组项数 `n` 与乘子有公因子时会「纹丝不动」——`n=7` 时 `step*7 % 7 ≡ 0`，`n=5` 时 `step*5 % 5 ≡ 0`。改为 `rollIdx(step,k,n)` 用质数乘子 7919（与任何 `n < 7919` 互质），保证相邻帧必然换候选。
2. **轮播间隔必须等于心跳间隔**：`ROLL_MS` 原为 90ms 而心跳 70ms，会出现「某一心跳帧内容没变」的顿感；改为 70ms，每推一帧必换一字。

#### 落定行上底色

模板三行改为 `background-color: {{ lineHotK ? theme.cardLight : 'transparent' }}`，**只有落定的行有底色条**，滚动行永远是灰字。于是「逐条落定」在视觉上就是逐条出现的结果条，抽两个也自动复用同一效果。行样式从 `height:34` 改为 `height:30 + margin:2px 0`，三行总高仍 102px（< 舞台 126px），块重心不随内容增减跳动。

**静态验证**：`node --check` 通过；模板引用字段全部已声明（0 缺失）；三行无 `display` 三元、无 `if`、无 `for` 数组（继续规避 §7.8 的隐藏子树与数组不重绘两个真机坑）；`frameAt` 时序仿真：t=0/140/280 仅第 1 行滚动且后两行空、t=420 第 1 行定住且第 2 行起滚、t=860 前两行定住且第 3 行起滚、t=1300 三行全定，边界断言（419/859/1299 未定）全通过；抽一个/抽两个时序回归不变（800ms 单定 / 533+1066ms 双定）。

**验收边界（未闭环）**：与 §7.9 相同——Mac 抓不到手环画面，**「点『抽三个』能看到逐条落定过程、三条都出结果、按钮 2 秒内自动恢复」仍需 Tom 真机肉眼复核**；安装回执不算功能证据。若真机仍停在「抽取中」，2 秒后再点一次必出结果（第三层兜底）。
